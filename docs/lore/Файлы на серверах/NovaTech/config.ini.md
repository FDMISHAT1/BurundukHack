# config.ini

> Конфигурационный файл базы данных с паролем в открытом тексте. Ключевой файл для прогресса [[Миссия 1 — Первый контакт|миссии 1]].

## Расположение

`/opt/config.ini` на рабочей станции dev-workstation (192.168.1.10)

## Содержимое файла

```ini
[database]
db_host=192.168.1.20
db_user=dbadmin
db_pass=S3cureDB!
db_name=customers
```

## Нарративная функция

- **Критическая находка**: даёт игроку учётные данные для подключения к DB-серверу (192.168.1.20)
- **Пароль в открытом тексте** -- [[Burunduk]] комментирует это:

```
[burunduk]: db_user: dbadmin, db_pass: S3cureDB!
            Пароль хранится в открытом тексте в конфиг-файле.
            На рабочей станции, доступной по SSH со слабым паролем.
            
            Знаешь, что самое грустное? Это не исключение.
            Это норма. Девяносто процентов взломов происходят
            потому что кто-то записал пароль на стикере.
            
            Попробуй этот пароль на сервере БД.
```

- **Реализм**: типичная ошибка настоящих разработчиков -- хранение credentials в plaintext конфигах
- **Путь к этому файлу**: игрок узнаёт из [[notes.txt (developer)]] или [[bash_history (developer)]]

## Связанные файлы

- [[notes.txt (developer)]] -- содержит путь к этому файлу
- [[bash_history (developer)]] -- developer обращался к этому файлу
- [[relay.conf]] -- скрытый конфиг ретранслятора (другой уровень доступа)
- [[auth.log (DB)]] -- логи на сервере, к которому ведёт этот пароль
